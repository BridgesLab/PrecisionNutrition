## Purpose

MRBEE (Lorincz-Comi et al., *HGG Advances* 2024) treats MR as an
**errors-in-variables** problem. GWAS effect estimates carry measurement error;
that error biases ordinary IVW, and the direction of the bias depends on sample
overlap while its magnitude depends on instrument strength. MRBEE subtracts the
bias exactly, using the estimation-error covariance matrix $R_{xy}$.

Two things make it a genuinely different check from what we have run:

1. **$R_{xy}$ is estimated from insignificant SNPs**, and its off-diagonal is a
   direct estimate of the correlation induced by sample overlap. This is a
   **third, independent measurement** of the same quantity as MR-APSS's $C_{12}$
   and CAUSE's $\rho$ — from a third model family.
2. **Pleiotropy is removed by iterative outlier detection** (IMRP) rather than
   modelled as a distribution. Like MR-RAPS it assumes the *remaining* pleiotropy
   is uncorrelated with instrument strength; unlike MR-RAPS it also corrects for
   overlap.

::: callout-important
MRBEE handles overlap, weak instruments and *uncorrelated* pleiotropy. It does
**not** model a shared confounder. If correlated pleiotropy is present, MRBEE is
biased in the same way MR-RAPS is — the outlier test removes variants that look
anomalous, not variants that are systematically confounded.
:::

fit_one <- function(arm, th) {
  d <- ivs[[arm]][[th]]
  if (nrow(d) < 4) return(NULL)

  # NOTE the argument names. The univariable entry point takes lowercase bx/bxse
  # as VECTORS; the multivariable MRBEE.IMRP() takes bX/bXse as matrices. Passing
  # the MVMR names to the UV function fails with "unused argument".
  res <- if (!is.null(getNamespace("MRBEE")$MRBEE.IMRP.UV)) {
    try(MRBEE::MRBEE.IMRP.UV(
      by = d$b.out, bx = d$b.exp,
      byse = d$se.out, bxse = d$se.exp,
      Rxy = Rxy[[arm]]
    ), silent = TRUE)
  } else {
    try(MRBEE::MRBEE.IMRP(
      by = d$b.out, bX = matrix(d$b.exp, ncol = 1),
      byse = d$se.out, bXse = matrix(d$se.exp, ncol = 1),
      Rxy = Rxy[[arm]], var.est = "ordinal"
    ), silent = TRUE)
  }

  if (inherits(res, "try-error")) {
    message("MRBEE failed for ", arm, " / ", th, ": ",
            conditionMessage(attr(res, "condition")))
    return(NULL)
  }
  tidy_mrbee(res, arm = arm, threshold = th, n_iv = nrow(d))
}

## Reading it

The most valuable single number here is `cov_overlap`. We now have three
independent estimates of sample overlap, from three model families — MRBEE's
error covariance, MR-APSS's cross-trait LDSC intercept, and CAUSE's $\rho$. If all
three agree the overlap picture is settled; if MRBEE's disagrees materially, the
LDSC-based estimates deserve a second look, since they rest on assumptions
(HapMap3 restriction, LD-score model) that MRBEE's does not.

`n_pleiotropic` is the second thing to check. A large number of removed
instruments means the IMRP test is doing heavy lifting, and the estimate is
conditional on those removals being the right ones — worth a sensitivity check
against MR-RAPS's `tukey` fit, which downweights rather than deletes.
